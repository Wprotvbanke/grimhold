# Git: что где лежит и как не потерять работу

Читать, когда садишься за проект на новой машине, когда непонятно, попадает ли
файл в репозиторий, и **раз в день — чтобы закоммитить**.

## Правило

**Коммит после каждой законченной задачи, push в тот же день.** Не «когда
накопится».

Это не педантизм. Однажды в истории проекта был один коммит, а в рабочей папке
147 несохранённых файлов: весь `docs/`, `CLAUDE.md` и дюжина исходников
никогда не попадали в git. Любая неудачная правка, `git checkout` или отказ
диска стирали недели работы — и восстановить было бы нечем.

## Что в git, а что нет

| Где | В git | Почему |
|---|---|---|
| `packages/*/src`, `scripts`, `docs`, `*.md` | да | это и есть проект |
| `packages/client/public/models`, `textures`, `draco` | **да** | без готовых ассетов игра не запускается |
| `assets/source/` | нет | исходники до обработки, 40 МБ; см. ниже |
| `packages/server/grimhold.db` | нет | пересоздаётся `npm run seed` |
| `node_modules`, `dist`, `*.log` | нет | ставится и собирается из исходников |
| `scripts/tmp-*`, `screenshot*.png` | нет | мусор отладки |

**Готовые ассеты лежат в git намеренно.** Они двоичные и весят около двадцати
мегабайт, но без них проект не собирается во что-то играбельное, а
воспроизвести их можно только из `assets/source/`, которого в репозитории нет.
Git LFS не заводим: двадцать мегабайт для GitHub — мелочь, а LFS добавил бы
лишнюю точку отказа и лишний шаг на новой машине.

**Подлинники ассетов живут в OneDrive** — в папках на рабочем столе, откуда их
брали (`hero`, `Nature`, `Buildings`, `lights`, `sky`, `Taverna Low Poly`).
OneDrive синхронизирует их сам, поэтому вторая копия в git не нужна. Источник
каждого готового файла записан в [assets.md](assets.md).

## Как поднять проект на чистой машине

```bash
git clone <адрес> grimhold
cd grimhold
npm ci
npm run seed        # учётная запись test / test123 и три персонажа
npm run dev         # сервер ws://localhost:8080, клиент http://localhost:5173
```

База и `node_modules` появятся сами. Ассеты приедут вместе с репозиторием.

Пересобирать ассеты нужно **только** если правишь `scripts/prepare-*.ts`. Тогда
верни исходники из OneDrive в `assets/source/` и запусти нужный скрипт — какой
именно, сказано в [assets.md](assets.md).

## Проверка, что копия настоящая

Репозиторий, из которого не собирается проект, — это не резервная копия.
Убедиться можно только сборкой с нуля, в стороне от рабочей папки:

```bash
git clone <адрес> /tmp/grimhold-проверка
cd /tmp/grimhold-проверка && npm ci && npm run check
npm run build -w @grimhold/client
```

Зелено — значит в репозитории есть всё нужное. Не собралось — значит нужный
файл попал под `.gitignore`, и чинить это надо сейчас, а не когда диск умрёт.

Стоит повторять после каждого крупного пополнения ассетов: именно там легче
всего случайно оставить файл за бортом.
