# Сквозные проверки

Читать, когда пишешь или чинишь проверку из `scripts/*-check.ts`.

Это не юнит-тесты: они ходят **в живой сервер** по настоящему протоколу,
поднимают персонажей, шагают ногами и смотрят на снапшоты. Поэтому запускать
их надо при поднятом `npm run dev`, а падают они не только от ошибок в коде,
но и от собственной торопливости.

```bash
npm run e2e · combat · pvp · dungeon · inventory · harvest · craft · bank · trade · netcode · gate
```

## Ждать факта, а не паузы

Главное правило, и оно выведено из провалов, которые «не воспроизводятся».

`await sleep(4500)` — это утверждение «сервер успеет за четыре с половиной
секунды». Оно верно ровно до первого изменения правил. Срок лежания вырос
с трёх секунд до десяти и стал удваиваться за каждую быструю смерть — и долгий
прогон, где проверку убивают не раз, начал давать провалы в случайных местах.
Найти их по логу нельзя: он говорит, что чего-то нет, и молчит о том, чего
ждали.

Поэтому есть `waitUntil(condition, timeoutMs)` (`scripts/testClient.ts`):
ждёт условия, возвращает `{ ok, waited }`. Предел берётся не «с запасом
на глазок», а из **самого долгого случая, какой сервер вообще может назначить**:

```ts
const limit = RESPAWN_DELAY * 2 ** RESPAWN_STREAK_MAX * 1000 + 3000;
const risen = await waitUntil(() => client.latestSnapshot?.self.alive === true, limit);
```

Не дождались — **сказать вслух, чего именно не дождались**, и сколько ждали.
Молчаливый провал обходится дороже самого падения.

Время ожидания стоит печатать и при успехе (`···  подъём занял 10.2 с`):
`check` показывает подробности только у провала, а ползущее время видно
заранее — до того, как оно упрётся в предел и проверка начнёт падать
«непонятно почему».

Фиксированная пауза уместна в одном случае: когда проверяешь, что чего-то
**не** произошло. «Сразу после смерти подъём ещё не происходит» — это именно
пауза, и другой она быть не может.

## Доказывать причину, а не совпадение

Проверка обязана падать по той причине, ради которой написана. Дважды
приёмка проходила по ложной: бойцы стояли вне досягаемости удара — «урона
нет» было правдой, но не той. Меряй расстояние, а не только исход.

## Числа брать из общего кода

`RESPAWN_DELAY`, `CHEST_TIME`, `BAG_SECONDS` — проверка ждёт по тем же
константам, по которым живёт сервер. Зашитое число расходится с правилом молча
и ровно в тот день, когда правило поменяли.

## Чего они не ловят

Всё, что видно только глазами: пропавшую текстуру, дрожащий камень, свет,
которого не видно за три шага. Сервер при этом стоит твёрдо, и ни одна
проверка не падает — расходятся картинка и правда.
См. [architecture.md](architecture.md), раздел про выводимый мир.
