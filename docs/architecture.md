# Архитектура

Читать, когда трогаешь сеть, протокол, устройство пакетов или добавляешь
команду. Про бой и движение — [combat.md](combat.md), про мир и постройки —
[blocks.md](blocks.md), про вещи — [loot.md](loot.md).

## Три правила, которые нельзя нарушать

Нарушение любого придётся откатывать.

**1. Клиент шлёт намерения, а не результаты.** Можно: «жму вперёд», «бью в этом
направлении», «перенеси предмет отсюда сюда». Нельзя: «моя позиция теперь X»,
«я нанёс 50 урона», «предмет теперь лежит здесь». Всё считает сервер.

Это подготовка к античиту: когда придёт время, проверки дописываются внутрь
готовых обработчиков, а не переписывается весь обмен. Античит-проверок пока
намеренно нет, но протокол под них готов.

**2. Состояние мира меняется только через слой команд**
`packages/server/src/commands/`. Обработчик имеет вид
`(ctx, payload) => GameEvent[]`. Ничто не мутирует `World` в обход.

**3. Операции с ценностями пишутся в базу немедленно** — см.
[storage.md](storage.md).

## Пакеты

```
packages/shared/   общий код клиента и сервера
packages/server/   авторитарный сервер: тик 20 Гц, сессии, хранилище
packages/client/   three.js: рендер, предсказание, интерфейс
scripts/           проверочные скрипты против живого сервера
```

## Почему shared именно такой

`shared` — не свалка утилит, а набор вещей, которые **обязаны совпадать** на
обеих сторонах, иначе игра ломается тихо.

| Файл | Что в нём и куда читать дальше |
|---|---|
| `movement.ts` | одна симуляция шага на сервер и клиент — [combat.md](combat.md) |
| `combat.ts` | фазы действий, общий множитель скорости — [combat.md](combat.md) |
| `chunks.ts`, `level.ts` | мир из коробок, генерация из координат — [blocks.md](blocks.md) |
| `items.ts`, `inventory.ts` | предметы и сетка рюкзака — [loot.md](loot.md) |
| `nature.ts` | раскладка растительности и стволы — [nature.md](nature.md) |
| `daytime.ts` | часы мира: время суток из номера тика — [sun.md](sun.md) |
| `protocol.ts` | схемы Zod. **Версия поднимается при любом изменении формата сообщений** |

## Как течёт кадр

**Сервер, 20 Гц** (`server/src/gameloop.ts` → `tickWorld`): движение игроков →
бой и фазы действий → ИИ мобов → снаряды → запись истории позиций → рассылка
снапшотов.

Все исходящие сообщения собираются в `Outbox` и рассылаются в `index.ts`,
поэтому игровая логика ничего не знает о сокетах и её можно гонять в тестах.
У `Outbox` есть канал на каждый род сообщений; если состояние игрока меняется
не по его команде, а по ходу тика — его надо туда положить, иначе клиент об
этом не узнает. Так уже было с лутом, см. [loot.md](loot.md).

**Клиент, каждый кадр** (`client/src/main.ts`): ввод применяется немедленно и
уходит на сервер → пришедший снапшот поправляет предсказание (`prediction.ts`)
→ камера идёт по предсказанию с затухающей поправкой → чужие рисуются с
задержкой 110 мс через интерполяцию (`interpolation.ts`) → подгружаются чанки
вокруг.

## Предсказание и реконсилиация

Клиент не ждёт сервера: применяет ввод сразу и запоминает его. Приходит снапшот
с номером последнего обработанного ввода — клиент ставит авторитетную позицию
и переигрывает поверх неё всё неподтверждённое. Остаточная ошибка гасится
затухающим смещением, а не рывком.

Работает это ровно потому, что обе стороны зовут одну `step()`. Ввод нарезан
фиксированным шагом 60 Гц, чтобы числа совпадали побитово. Проверяется
`npm run netcode`.

## Радиус интереса

Сервер шлёт только сущности в 45 метрах. Это и экономия трафика, и защита от
wallhack: данных о тех, кого не должно быть видно, у клиента физически нет.

## Инстансы

Изоляция строится на поле `instanceId`, а не на отдельных мап-левелах:
геометрия интерьеров будет лежать в том же мировом пространстве со смещением,
а игроки из разных инстансов просто не попадают в снапшоты друг друга.
Заложено с вехи 2 ради подземелий вехи 6.

## Клиентские подсистемы

- `prediction.ts`, `interpolation.ts` — своё движение и чужое, см. выше.
- `viewmodel.ts` — руки от первого лица — [hands.md](hands.md). Рисуются
  отдельной сценой поверх мира с очисткой буфера глубины, иначе вплотную
  к стене уезжают внутрь геометрии.
- `models.ts`, `stopmotion.ts` — загрузка моделей и анимации — [assets.md](assets.md).
- `scene.ts` — сборка мира: материалы и `scaleBoxUv` ([blocks.md](blocks.md)),
  чанки, и связывание всего, что ниже.
- `sky.ts`, `daynight.ts` — небо и смена суток — [sky.md](sky.md), [sun.md](sun.md).
- `lights.ts` — весь рукотворный огонь — [light.md](light.md).
- `nature.ts` — растительность пачками — [nature.md](nature.md).
- `buildings.ts` — то в постройках, чего не сделать коробкой — [buildings.md](buildings.md).
- `quality.ts` — разрешение подстраивается под машину — [performance.md](performance.md).
- `props.ts` — обстановка таверны — [buildings.md](buildings.md).
- `inventoryui.ts` — рюкзак — [loot.md](loot.md).
- `combatui.ts` — полоски, всплывающий урон, экран смерти — [combat.md](combat.md).
- `keyboard.ts` — клавиатура принадлежит игре, пока мышь захвачена или открыт
  рюкзак: браузерные умолчания гасятся, а в полном экране (F11 обрабатываем
  сами — нативный полный экран браузера странице захвата не даёт) подключается
  Keyboard Lock и отдаёт игре даже Ctrl+W. Обновление и отладка не отбираются.
- `ps1.ts` — обработка текстур под эпоху PlayStation для загружаемых моделей.
