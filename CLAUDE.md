# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Общение с пользователем, комментарии в коде и сообщения коммитов — по-русски.

## Что это

Grimhold — браузерная MMORPG от первого лица в мрачном средневековом фэнтези на
TypeScript и three.js. Meridian 59 как основа, PvP-флаги как в Lineage, расовое
ремесло как в Valheim, подземелья с выносом добычи как в Dark and Darker.
Главная фишка — подземелья: зашёл со своим снаряжением, набрал добычи, вышел
живым или потерял всё.

Сервер авторитарен, клиент предсказывает своё движение. Монорепа:
`packages/shared` (общий код), `packages/server`, `packages/client`, `scripts`.

**Состояние:** вехи 1–6 закрыты. Веха 6 — подземелья — собрана целиком:
три этажа из комнат в одном инстансе, лестницы в нишах, сундуки и обитатели,
цена смерти внизу (надетое пропадает, рюкзак остаётся мешком), общий зал
на двенадцать, темнота с мглой на пять метров и факел в руке — свет в обмен
на щит и на то, что тебя видно. Внизу флаги не действуют: все всем враги,
и отличить своих даёт только отряд (**G**). Вылазка кончается «Хозяином
глубины» на дне: пока он жив, порталы заперты всему инстансу, его смерть
открывает их на две с половиной минуты. Вся добыча — и с убитых, и из
сундуков — берётся руками из мешка: игрок сам решает, что унести.
Идёт веха 7 — атмосфера и содержание. **Звук сделан и принят на слух**:
шаги, бой, работа, фон подземелья, чужой сундук слышен соседям, музыка
города по сценарию (день и ночь) — см.
[docs/sound.md](docs/sound.md). Графика: постобработка (F1 «Эффекты»),
рельеф камня, туман у земли, пыль и мошкара.

**Оружие видно в руках**: топор зажат в кулаке и машет клипом владельца,
рядом с ним в той же таблице хвата живёт посох мага —
хват, посадка и замах описаны в [docs/hands.md](docs/hands.md); клипы
от владельца сделаны на нашем риге, и так их надо просить впредь. Темп
и цена удара зависят от того, что в руке ([docs/combat.md](docs/combat.md)):
топор бьёт вдвое реже кулака, а кулаком махать вдвое дешевле.

После авторизации — **лобби** ([docs/lobby.md](docs/lobby.md)): на заднике
во весь рост стоит живая модель выбранного персонажа, слева его собратья
по учётной записи, внизу «Играть». Там же персонажа создают и **стирают
насовсем** — вписав его имя руками. Играет при этом **главная тема** игры. При входе в мир — **экран загрузки**
с картинкой и полосой ([docs/performance.md](docs/performance.md)).

**Магия — это свитки в клетках умений** ([docs/magic.md](docs/magic.md)):
класс задаёт только уклон, а умеет персонаж то, что вставил в двенадцать
несгораемых клеток под рюкзаком. Свитки читают с панели быстрого доступа —
в ней теперь десять ячеек (1…9 и 0), и цвет свитка виден без чтения.
**Мана сама не восстанавливается** — только «Настоем разума» или медитацией,
а медитация держит на месте и после подъёма семь секунд не пускает обратно;
пока она идёт, края кадра затемнены виньеткой ([docs/camera.md](docs/camera.md)
— там же порядок слоёв поверх кадра и правила для будущих эффектов).

**Вещи и обиход** ([docs/loot.md](docs/loot.md)): зелья пьются с откатом
(отсчёт виден на ячейке панели) и **вливаются тиками** — полоса жизни при
этом зеленеет; одинаковые стопки складываются перетаскиванием; у предмета
может быть картинка. Ночью на небе луна ([docs/sky.md](docs/sky.md)).

**Город перестроен моделями**: 84×84 м, каменные стены с вышками и арками,
казна-ларец, дома кварталами вдоль улиц к воротам (деревенский пак, восемь
видов) и таверна с залом, в который входят, — мебель, факелы, своя музыка. См.
[docs/buildings.md](docs/buildings.md).
Дальше в вехе: вторая зона, сервер в сети.

Мир при этом уже одет: небо, смена дня и ночи, уличный огонь, лес — см.
разделы ниже.

Прокачка идёт **двумя дорожками**: навыки учатся сами от того, чем
пользуешься, а за победы копятся очки, которые игрок вкладывает в жизнь,
стамину или ману руками. Подробности и числа — [docs/skills.md](docs/skills.md).

## Запуск

```bash
npm run dev     # сервер ws://localhost:8080, клиент http://localhost:5173
```

Вход: `test` / `test123` (три персонажа). Пересоздать — `npm run seed`.

В игре: **F1** — настройки картинки и звука, **F2** — служебное меню ведущего (выдать
себе предмет, перевести часы, отпереть порталы подземелья, телепорт в точку,
ранить себя — полосу жизни и лечение иначе не посмотреть). Кому оно открыто,
решает запуск сервера: `GRIMHOLD_ADMINS=имя,имя`, по умолчанию — `test`
и `Копатель` (аккаунт сквозной проверки подземелья).

| Команда | Что делает |
|---|---|
| `npm run check` | тесты и типы всех пакетов и скриптов |
| `npm test` · `npx vitest run <файл>` | юнит-тесты целиком или один файл |
| `npm run e2e` · `combat` · `pvp` · `dungeon` · `inventory` · `harvest` · `craft` · `bank` · `trade` · `netcode` · `gate` | сквозные проверки |
| `npx tsx scripts/prepare-*.ts` | пересобрать ассеты — см. [docs/assets.md](docs/assets.md) |
| `npx tsx scripts/screenshot.ts` | снимок игры браузером против запущенного `dev` |
| `npm run roster` | сводка по населению мира |

Сквозные проверки работают **против запущенного сервера** — сначала `npm run dev`.
Как они устроены и почему ждут факта, а не паузы, — [docs/checks.md](docs/checks.md).

## Правила, которые нельзя нарушать

1. **Клиент шлёт намерения, а не результаты.** Всё считает сервер.
2. **Состояние мира меняется только через слой команд** `server/src/commands/`.
3. **Операции с ценностями пишутся в базу немедленно**, остальное — пакетом.
4. **Только CC0-ассеты.** Unity Asset Store не годится.
5. **Тесты — только на базовое поведение.** Не обкладывать каждую мелочь.
6. **Коммит после каждой законченной задачи**, push в тот же день — см.
   [docs/git.md](docs/git.md). Однажды в истории был один коммит и 147
   несохранённых файлов, включая весь `docs/`.
7. **Что клиент выводит сам — о том ему надо сказать.** Геометрия по сети
   не ездит: землю клиент строит по имени инстанса, ноды и сундуки — по зерну.
   Значит любое изменение исходных данных обязано уйти сообщением, и слать его
   надо **из места изменения**, а не из команды: иначе один из путей забудут.
   Ошибки этого рода не ловятся проверками данных — сервер стоит твёрдо,
   расходятся картинка и правда.

Подробности и обоснования — в файлах ниже.

## Как вести документацию

**Обновлять по ходу работы, а не по отдельной просьбе.** Этот файл подгружается
в контекст автоматически и потому единственный, который новая сессия
гарантированно прочтёт: устареет он — устареет вся сессия.

Держать его коротким: здесь навигатор и правила, подробности живут в `docs/`.
Каждая строка тут стоит токенов в каждой сессии, строка в `docs/` — только когда
файл открыли.

Обновлять, когда закрыт этап или веха, изменилась архитектура, добавилась
команда или обнаружена ловушка, на которую уже наступали.
